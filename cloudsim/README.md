# CloudSim Provisioning Simulation

This directory contains the Java-based CloudSim evaluation module (`ProvisioningSimulation.java`), which bridges the machine learning workload predictions from the MTTD framework into cloud resource provisioning simulations.

---

## 1. Purpose

The simulation evaluates how workload prediction accuracy translates into actual cloud infrastructure metrics:
- Virtual Machine (VM) provisioning efficiency (total VM-hours)
- Resource waste caused by over-provisioning (wasted VM-hours)
- SLA violations caused by under-provisioning (cloudlets taking longer than 3,600 s)
- Under-provisioned hours where allocated capacity was insufficient
- Average makespan (completion latency) for request processing

It models a cloud data center receiving hourly traffic loads based on the predictions generated by `mttd_bridge.py`.

---

## 2. Requirements

- **Java Development Kit (JDK):** JDK 11 or newer (the published results were evaluated with OpenJDK 21).
- **CloudSim 3.0.3 JAR:** Download the release archive from [CloudSim 3.0.3 Release](https://github.com/Cloudslab/cloudsim/releases/tag/cloudsim-3.0.3).
  Extract `cloudsim-3.0.3.jar` from `cloudsim-3.0.3/jars/cloudsim-3.0.3.jar`.

---

## 3. Compilation and Execution

### Compilation

From within the `cloudsim/` directory (or pointing `-cp` to the jar location):

```bash
# Linux / macOS
javac -cp cloudsim-3.0.3.jar -d build ProvisioningSimulation.java

# Windows PowerShell
javac -cp cloudsim-3.0.3.jar -d build ProvisioningSimulation.java
```

### Execution

Run the simulation from the folder containing the prediction CSV files (e.g., `results/cricket/`):

```bash
# Linux / macOS (colon classpath separator)
java -cp build:cloudsim-3.0.3.jar mttd.ProvisioningSimulation

# Windows PowerShell (semicolon classpath separator)
java -cp "build;cloudsim-3.0.3.jar" mttd.ProvisioningSimulation
```

### Custom Input Files / Daily Retraining Run

`ProvisioningSimulation.java` supports three optional command-line arguments:
- `args[0]` = with-retraining predictions CSV (default: `predictions_retrain.csv`)
- `args[1]` = no-retraining predictions CSV (default: `predictions_noretrain.csv`)
- `args[2]` = output CSV (default: `cloudsim_results.csv`)

To run with daily-retraining predictions from the reselection study:

```bash
# Linux / macOS
java -cp build:cloudsim-3.0.3.jar mttd.ProvisioningSimulation predictions_daily_retrain.csv predictions_noretrain.csv cloudsim_results_daily.csv

# Windows PowerShell
java -cp "build;cloudsim-3.0.3.jar" mttd.ProvisioningSimulation predictions_daily_retrain.csv predictions_noretrain.csv cloudsim_results_daily.csv
```

## 4. Evaluated Provisioning Policies

For each simulated hour, the datacenter provisions VMs according to five distinct policies:

1. **`REACTIVE` (Threshold Autoscaler Baseline):**
   Provisions VMs based on the previous hour's observed load ($t-1$).
2. **`MTTD-noRetrain`:**
   Provisions VMs using forecasts from the candidate model selected at initialization, without subsequent adaptive retraining (`predictions_noretrain.csv`).
3. **`MTTD-Retrain` (Full Adaptive MTTD):**
   Provisions VMs using forecasts from the active model in the adaptive MTTD framework with two-strike retraining (`predictions_retrain.csv`).
4. **`ORACLE` (Upper Bound):**
   Provisions VMs using the exact actual load of the current hour ($t$), representing perfect foresight.
5. **`MTTD-Hybrid`:**
   Provisions VMs using $\max(\hat{y}_t, y_{t-1})$. Combines MTTD proactive predictions with the reactive floor to guard against under-provisioning during bursty load spikes.

---

## 5. Metrics Definitions

| Metric | Definition | Impact |
|---|---|---|
| **VM-Hours** | $\sum_{t=1}^{N} \text{Allocated VMs}_t$ | Total computing resource consumption |
| **Wasted VM-Hours** | $\sum_{t=1}^{N} \max(0, \text{Allocated VMs}_t - \text{Required VMs}_t)$ | Economic cost of over-provisioning |
| **SLA Violations** | Count of hours where cloudlet makespan exceeded 3,600 s | Quality-of-service degradation |
| **Under-provisioned Hours** | Count of hours where $\text{Allocated VMs}_t < \text{Required VMs}_t$ | Capacity deficit indicating imminent SLA risk |
| **Average Makespan** | Mean completion time of all cloudlets across all simulated hours | Service latency |

Capacity model parameters:
- 1 VM capacity: 4,000 requests/hour (1,000 MIPS)
- Cloudlet size: 200 requests (900 MI/request)
- Headroom buffer: 10% extra capacity (`HEADROOM = 1.10`) for proactive policies
- Max datacenter capacity: 150 VMs
- SLA deadline: 3,600 s per 1-hour slot

---

## 6. Simulation Configuration and `MAX_HOURS`

- **`MAX_HOURS = 0` (Full Run):**
  Simulates all 1,080 deployment hours (default). All published results must be obtained with `MAX_HOURS = 0`.
- **`MAX_HOURS > 0` (Test Run):**
  Limits the simulation to the first $N$ hours for quick verification and debugging.
